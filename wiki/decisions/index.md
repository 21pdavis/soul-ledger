# Accepted decisions

* [0001: Public site from day one, cached in our own Postgres](0001-public-site-postgres-cache.md) - The site is public at launch and every player lookup is cached in our Postgres so each match is fetched from the API only once.
* [0002: Identify players by Steam URL/ID with no login, plus a squad mode](0002-steam-id-no-login.md) - Players paste a Steam profile URL or ID with no login, Steam OpenID may come later, and friends can load each other into a squad comparison.
* [0003: Linear Wrapped story first, then a dashboard hub; story must be shareable](0003-story-then-dashboard.md) - The experience is a linear Wrapped story followed by an explorable dashboard, and the story must be exportable and shareable.
* [0004: All-time by default, with a this-patch toggle](0004-time-window.md) - Stats default to the player's all-time history, with a toggle to show only the current patch.
* [0005: Stack is Next.js + R3F/drei + Framer Motion + Neon Postgres on Render](0005-stack.md) - The app is built with Next.js (TypeScript), React Three Fiber/drei and Framer Motion, stores data in Neon Postgres, and deploys on Render.
* [0006: Royalty-free or commissioned occult-jazz music, synthesized stingers, muted until click](0006-audio.md) - Music is royalty-free or commissioned 1920s-occult-jazz, UI stingers are synthesized with Web Audio, audio stays muted until a start-splash click, and Valve audio is never used.
* [0007: Tone is mostly hype with a roast slide or two](0007-tone-hype-with-roasts.md) - Copy and slides are celebratory by default, with one or two playful roast slides.
* [0008: Rank against global percentiles and a site Hall of Fame](0008-ranking-population.md) - Players get global percentiles from API distributions plus a site-only Hall of Fame for niche stats.
* [0009: Preview story from stored data, then a second step unlocks full history](0009-preview-then-full-history.md) - v1 renders a preview from whatever history the API already holds, then invites the player to unlock full history.
* [0010: Squad mode via a shareable link of up to 6 players, with role assignment](0010-squad-mode.md) - Friends compare via /squad?ids=..., up to 6 players, with assigned team roles and a comparison table.
* [0011: Share via PNG cards plus a hosted story link](0011-sharing.md) - Exports are PNG cards per slide plus a summary card, and every story also gets a shareable URL viewable on the site.
* [0012: Phone-first 9:16 story; the 3D backdrop fills desktop width](0012-phone-first.md) - The story is designed as a vertical 9:16 tap-through, and on desktop the 3D scene fills the extra width.
* [0013: Build our own low-poly hero models from reference images](0013-custom-low-poly-models.md) - The 3D uses custom stylized low-poly hero models made from API hero images and other reference views; no ripped game models.
* [0014: Themed loading in stages with sneak peeks](0014-staged-loading.md) - The wait for data is the intro, revealed in stages that tease upcoming slides; the start click unlocks audio.
* [0015: v1 story slide list](0015-v1-slides.md) - The v1 Wrapped story slides, with the scavenger stats merged onto one card, kill-breakdown slides and an MVP signature-stat slide.
* [0016: Open source, funded by Patreon/Ko-fi, no ads or paywalls](0016-open-source-patreon.md) - The project is open source and funded by donations; no ads and no paywalled stats; cosmetic perks maybe later.
* [0017: Full history for development comes from the user's own $1.50 deadlock-api Patreon tier](0017-full-history-via-patreon-for-now.md) - For now the user subscribes to the deadlock-api Patreon tier and tests with their own account; outreach to maintainers waits until launch (outreach superseded by ADR 0058).
* [0018: Shared stories are frozen JSON snapshots with OG images](0018-story-snapshots.md) - Each shared story is a frozen JSON snapshot at /w/<slug> with a generated preview image and a see-my-latest button.
* [0019: Build stylized low-poly models for all heroes in code](0019-code-built-hero-models.md) - All playable heroes get stylized low-poly models built procedurally in code (Three.js primitives), using API images and other views as reference.
* [0021: Two kill slides; MVP is the most extreme percentile stat](0021-kill-slides-and-mvp.md) - "How you kill" and "Precision" are separate slides; the MVP signature stat is the player's most extreme percentile, compared against same-hero players where possible.
* [0022: The product is named Soul Ledger](0022-name-soul-ledger.md) - The site is called Soul Ledger; "Wrapped" is used only in descriptive copy.
* [0023: Everyone looked up is listed in the Hall of Fame, with a removal request](0023-hall-of-fame-privacy.md) - Any looked-up player can appear on the Hall of Fame under their Steam name; a removal request form handles opt-outs.
* [0024: License is AGPL-3.0](0024-license-agpl.md) - The repo is licensed AGPL-3.0 so hosted modified copies must publish their changes.
* [0025: Hero models are flat-shaded faceted low-poly with simple part animation](0025-model-style.md) - Code-built hero models use a flat-shaded faceted style built around silhouette and signature prop, with part animation and no skeletal rigs.
* [0026: Fetch inside Next.js server routes with a Postgres job table](0026-fetch-in-next-routes.md) - API fetching runs in Next.js server routes, coordinated by a Postgres job table/lock, streaming progress to the loading screen.
* [0027: Real royalty-free tracks for the theme plus generative Tone.js layers](0027-music-sourcing.md) - Claude shortlists CC0/royalty-free 1920s jazz/noir tracks for the user to pick; transitions use generative Tone.js stingers and drones.
* [0028: v1 milestones M1-M6; works on phone and desktop web; dashboard after v1](0028-milestones.md) - v1 ships in six milestones from data layer to Hall of Fame and must work on both phone and desktop web.
* [0029: Comprehensive testing is the cornerstone; TDD where possible](0029-testing-tdd.md) - Comprehensive unit and integration tests are the cornerstone of the project, written test-first wherever possible.
* [0030: Repo renamed to soul-ledger](0030-rename-soul-ledger.md) - The repo directory is renamed from deadlock-wrapped to soul-ledger at the start of the next session.
* [0031: Visual identity is art-deco occult](0031-visual-identity.md) - UI uses an art-deco occult look: deco display type, clean grotesk numerals, ink/bone palette with Patron-green and brass, ledger motifs.
* [0032: Private GitHub repo now, CI on every push, public at M2](0032-github-private-ci.md) - The repo lives on GitHub (21pdavis/soul-ledger), private until milestone M2, with GitHub Actions running all tests on every push.
* [0033: Neon project soul-ledger with main and dev branches](0033-neon-project.md) - Postgres is the Neon project soul-ledger (aws-us-west-2, PG 17) with a main branch for production and a dev branch; tests use throwaway databases.
* [0034: Tooling is pnpm, Vitest, Playwright, Drizzle, ESLint and Prettier](0034-tooling.md) - Package manager pnpm; Vitest for unit/integration tests; Playwright for e2e on phone and desktop; Drizzle ORM; ESLint and Prettier.
* [0035: The current patch starts on the date in the newest changelog title](0035-patch-date-from-changelog-title.md) - The this-patch window starts at UTC midnight of the MM-DD-YYYY date in the newest /v1/patches title, falling back to pub_date.
* [0037: Squad roles list, without The Backseat Gamer](0037-squad-roles-without-backseat-gamer.md) - Nine squad roles, each awarded for the highest per-match value of one stat; The Backseat Gamer (pings) is dropped.
* [0038: A one-trick plays their main in at least 50% of matches](0038-one-trick-threshold-50.md) - The roster slide labels a player a one-trick when their most-played hero accounts for 50% or more of counted matches, otherwise flex.
* [0039: Deploy from main via a Render Blueprint on the free plan](0039-render-free-blueprint.md) - The app deploys as one free-plan Render web service in Oregon, defined in render.yaml, built from main after PR review, using the migrated Neon main branch.
* [0040: M1 implementation choices confirmed; parry king at 60%](0040-m1-implementation-choices.md) - Confirms M1's libraries, flattened stat schema and tuning values as built, and sets the parry-king line at a 60% success rate.
* [0041: CHANGELOG.md plus a tagged GitHub Release per milestone](0041-changelog-and-releases.md) - Release notes live in CHANGELOG.md (Keep a Changelog); each milestone is a minor version tagged and published as a GitHub Release, with an in-app What's new page later.
* [0043: Staging access by secret link and 90-day cookie, replacing Google sign-in](0043-staging-access-link.md) - The staging gate admits a browser that opened a link carrying STAGING_ACCESS_KEY (then a signed 90-day cookie) or a request with that key in the x-staging-token header; Google sign-in is dropped.
* [0044: PRs gate every change; agent review before merging into staging](0044-pr-gated-changes-and-agent-review.md) - Every change goes through a PR with green CI; agents merge into staging only after an independent agent review whose feedback they act on; the owner hears about every merge and alone merges into main.
* [0045: Lighter wiki upkeep: CI checks the bookkeeping, the log records only what matters](0045-lighter-wiki-upkeep.md) - The OKF wiki stays, but pnpm check:wiki enforces its structure in CI and log.md records only decisions, research, new concepts, deprecations and milestones.
* [0046: Strict red-first TDD on every behaviour change](0046-strict-red-first-tdd.md) - TDD is mandatory, not "where possible" - every behaviour change is red, green, refactor with the failing test run and seen failing first, and PRs show the evidence.
* [0047: Streamlined review and CI: re-review only for blocking findings, one CI run per change, docs-only fast path](0047-streamlined-review-and-ci.md) - Re-reviews happen only after blocking findings or substantial fixes; each review round's fixes go in one commit; CI runs once per change and skips tests for docs-only PRs; reviewer effort scales with the change.
* [0048: Hard limits in .claude/settings.json and an escalation procedure for unattended runs](0048-unattended-run-guardrails.md) - Claude Code permission rules deny pushes to main/staging, force-pushes, destructive Neon actions, Render env changes and reading .env files, while routine commands are pre-allowed; blocked runs commit their work, write up options and send a push notification.
* [0049: Agent models: qa moves to Haiku 5.5, the other agents keep their models](0049-agent-model-assignment.md) - The qa agent runs on Haiku 5.5 and implementer and wiki-keeper stay on Sonnet; the reviewer row was amended by ADR 0057 (Sonnet, Opus only for security work).
* [0050: M2 story flow: phone tap-through and desktop pinned snap-scroll over one slide index](0050-m2-story-flow-and-controllers.md) - The story is a 9:16 tap-through on phones and a pinned 9:16 column with scroll-snap checkpoints on desktop, both driven by one shared slide index and the same slide components.
* [0051: M2 look and styling: deco typography placeholders, Framer Motion, CSS modules, no Tailwind](0051-m2-visual-motion-styling-stack.md) - M2 uses typography and deco shapes as placeholder art, Framer Motion for motion, CSS modules with palette tokens as CSS variables and next/font fonts, and no Tailwind.
* [0052: M2 entry, staged loading, error and completeness states](0052-m2-entry-loading-error-states.md) - A URL entry screen with an All time / This patch window control, three real loading stages from the NDJSON stream, in-voice full-screen error states, and a matches-count line with a Refresh action.
* [0053: M2 copy rules and data-presentation choices](0053-m2-copy-and-data-presentation.md) - Claude drafts the copy in one module with one fixed headline per slide; heroes, death heatmap, unspent souls, rank and MVP each have a fixed M2 presentation.
* [0054: M2 testing layers and accessibility rules](0054-m2-testing-and-accessibility.md) - M2 adds component tests per slide, phone and desktop Playwright suites with a mocked NDJSON lookup, and an accessibility baseline checked by tests.
* [0055: Owner confirmations after M2: names, fonts, caption, unspent-souls number deferred](0055-owner-confirmations-after-m2.md) - The owner confirmed the rank tier names and the Limelight and Space Grotesk pairing, chose urns returned for the Urn Mule caption, and deferred any unspent-souls number.
* [0056: Loader pacing: minimum dwell per stage, real events still gate stages](0056-loader-pacing.md) - The staged loader holds each real stage on screen for a minimum time and holds the story back for the last stage's dwell plus a tail, so a quick lookup can be read; a timer never advances a stage.
* [0057: Token-efficient unattended runs](0057-token-efficient-unattended-runs.md) - Eleven policies that cut token use in agent runs: orchestrator context hygiene, fresh narrow subagents, short briefs and reports, cheaper models and effort (reviewer on Sonnet, Opus for security work), foundation-first and fewer PRs, targeted tests, bounded fix loops, per-milestone measurement, small always-loaded context, and CI watched by the orchestrator.
* [0058: Contact the deadlock-api maintainers, and never work around their rate limits](0058-contact-maintainers-and-respect-rate-limits.md) - Outreach to the deadlock-api maintainers moves from deferred to planned, and Soul Ledger will not rotate IPs or otherwise evade per-IP limits; self-hosting a clone of the API is rejected.
* [0059: Claude posts as a GitHub App bot](0059-claude-posts-as-github-app-bot.md) - Reviewer and QA agents post PR comments and issues as the "Soul Ledger Claude" GitHub App through pnpm bot:gh, so they no longer appear as the owner.

# Superseded decisions

* [0020: Squad roles list and assignment](0020-squad-roles.md) - Ten squad roles, each awarded for the highest per-match value of one stat; every player gets one headline role, and extras show as badges.
* [0036: A one-trick plays their main in at least 60% of matches](0036-one-trick-threshold.md) - The roster slide labels a player a one-trick when their most-played hero accounts for 60% or more of counted matches, otherwise flex.
* [0042: A private staging environment behind Google sign-in, fed by a staging branch](0042-staging-environment.md) - Staging is a second Render service deploying the staging branch against a Neon staging branch; its environments and branches still stand, while its Google sign-in was superseded by ADR 0043 and its merge rule by ADR 0044.
* [0060: M2 open questions closed: fonts, rank names, hero art, no unspent souls](0060-owner-decisions-m2-open-questions.md) - The owner kept Limelight and Space Grotesk, accepted the rank tier names, allowed deadlock-api hero art with a Valve disclaimer, and dropped the unspent-souls stat.
* [0061: Parry king starts at a 40% success rate](0061-parry-king-at-40-percent.md) - The owner lowered the parry-king line from 60% to 40% of parries landed, because a player at 40% or higher is not a clown; this supersedes the parry line in ADR 0040.
* [0062: Desktop story is a vertical stack of wide cards](0062-desktop-vertical-card-stack.md) - On desktop the story is a vertical page of wide cards, one per slide, that scrolls down card by card with a vertical progress rail, replacing the pinned 9:16 column; phone is unchanged.
* [0063: Two-depth CI: smoke end-to-end on PRs into staging, full suite with coverage into main](0063-two-depth-ci.md) - A PR into staging runs format, lint, typecheck, unit tests and a smoke browser set; the staging to main PR and pushes to main run the full browser suite and unit tests with coverage.
* [0064: Show recent win rates next to all-time](0064-recent-win-rates.md) - The main and roster slides show the all-time win rate beside a recent one (latest 300 matches overall, latest 20 per hero), with an arrow when they differ by 3 points or more.
* [0065: Show deadlock-api hero images on tiles, downloaded into the repo](0065-hero-art-served-locally.md) - The owner approved showing deadlock-api hero images on hero tiles (staging included), served from copies downloaded into public/heroes, with the monogram as the fallback.
* [0066: The roast slide's death heatmap is drawn on a stylised Deadlock map](0066-death-map-on-roast-slide.md) - The death heatmap sits on a stylised map of the lanes and objectives (decorative, with the plot's title and description as the text alternative) on a finer 20 by 20 grid, replacing the abstract frame.
* [0067: The sites log in to the database with a limited app login; the owner login is for migrations](0067-database-logins-per-environment.md) - Production and staging connect as soul_ledger_app (read and write rows only), the production owner password lives only in the owner's password manager, and the owner login is kept for migrations.
* [0068: M3 scope and order: a story-following world, art cards for every hero, low-poly models after a checkpoint](0068-m3-scope-and-order.md) - M3 builds a Deadlock-flavoured 3D world that follows the story, with hero art cards for every hero, nemesis duels, three graphics levels, and low-poly posed models that start with a three-hero checkpoint.
* [0069: M3 world is a low-poly City Never Sleeps tour; heroes stay art cards for 0.3.0](0069-m3-city-tour-and-hero-cards.md) - The M3 world is a static low-poly copy of the post-update map that the camera tours lane by lane, and heroes appear as art-card cut-outs in 0.3.0 because code-sculpted hero models did not reach the quality bar.
* [0070: The graphics button is a cube icon in the screen's bottom-right corner](0070-graphics-button-is-a-corner-icon.md) - The graphics-level control is a small cube icon fixed in the bottom-right corner of the screen, outside the story frame, on every device; on desktop it widens on hover or focus to name the level.
* [0071: Remember an automatic graphics drop, but never save one to Off](0071-remember-auto-drop-but-never-save-off.md) - An automatic graphics drop to Simple is saved on the device, a drop to Off lasts only for the visit, and Off is only ever saved by the reader's own choice.
* [0072: Concise agent reviews, one thread per finding](0072-concise-reviews-one-thread-per-finding.md) - The reviewer agent posts only problems, one comment per finding with inline suggested changes where possible, and a re-review waits until every thread is resolved or marked blocked (rare).
